## 运行结果如何解释

- 条件1在LongBench有95题未观察到原文证据。条件2至4要求依赖文档的任务在作答前实际观察来源，无来源时明确弃答，三组各有24题弃答。其余101题有初稿，其中22题正确。来源约束让更多任务取得原文，但“观察到来源”不等于找到了支撑答案的证据。
- 条件2至4的LongBench检索调用了115次树搜索和67次计算，没有执行图查询。旧v2在106题实际查询了实体邻居。两种控制协议、证据和回答接口同时有变化，不能把分差单独归因于图，也没有验证中文图的收益。四个 v3 条件均未在这两套数据中实际选用图工具。
- 条件2的LongBench有20次复核格式错误。适配器在复核前已保存初稿，异常行仍按初稿计分，其中5题正确；条件3把这些情况显式记为保留初稿，消除了异常状态，分数不变。数学旧适配器在最终接口返回后才写答案；条件2一次最终截断、一次复核截断实际造成两题输出失败。条件3/4为各自的三题恢复了已经完整生成的答案字段，仍标注说明不完整。
- 条件3的LongBench复核由错改对3题、由对改错6题。条件4全局关闭复核，准确率回到初稿的22/125；作答模型逻辑请求由751降为623。该消融在03:22固定，两套数据统一开关，不按题或分数路由。条件3/4的LongBench请求全部命中精确缓存，因此没有重新进行这些请求的模型推理，不能从其墙钟时间推断推理提速。
- 条件3还改变了数学最终字段顺序，可能改变模型生成，和条件2的分差不是纯异常处理消融。条件4的数学输入/初稿来自同一请求条件，关闭复核后比条件3高1.625分。最新独立在线案例只有6/7通过：同一0.8B模型仍可能读到正确日期却反选标签，复核也会犯错。

## 数据、模型与评分

所有条件沿用原数据、连续教材、片段划分、树和实体图。MATH按旧协议将1110条 `content` 按JSONL顺序以两个换行拼成868,815字符，保留噪声和格式；连续正文 SHA-256 为 `811099c714f0e0d0182570d94b34910302617ebf1ed70ec6cfe3fd6449b5f2bc`。运行时只按 token 预算从原文选连续窗口并记录偏移。旧索引共126份，沿用原文件，当前指纹和文件时间见[索引记录](../artifacts/repar_v3_development_20261119/reused_index_fingerprints.json)。历史协议未冻结索引文件的字节哈希；逐题校验的是旧索引正文与原文一致以及引用偏移准确。

作答仍是本地9091的 Qwen3.5-0.8B 标准 Q4，关闭 thinking 和 MTP。MATH 最终输出上限4096 tokens；LongBench 初稿上限128 tokens，开启复核的条件另有每次2048 tokens上限和一次有界格式修复。MATH 选择题使用确定性规则，非选择题由9090的 Qwen3.8-27B匿名双评，有分歧时三评，按小问取中位。判分依据是数学正确性、论证和部分分规则，参考解法可替换为等价解法或证明。表中是实验折算分。使用同一评阅模型的多次判分可能相关。

两个测试集此前已被查看。这些是完整开发结果，不能作为未见测试确认。历史基线直接引用原报告；v3 的调用和输出契约有变化，不能把分差全部归因于检索。逐题配对差异、描述性区间及各阶段 token 口径见[综合报告](../artifacts/repar_v3_development_20261119/REPORT.md)和[机器汇总](../artifacts/repar_v3_development_20261119/summary.json)。
