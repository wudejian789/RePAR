# RePAR下一版：通用执行与证据管理优化方案

状态：**历史设计提案**。当前默认仍为v2。本文面向任意知识库、语言和研究任务，提出通用机制的分阶段设计。

后续更新：部分通用机制已落地，见[v3 实现](REPAR_V3_DESIGN.md)和[四组全量实验](REPAR_V3_EXPERIMENTS.md)。实现沿用原文和v2索引；多语检索、实体作用域和更强的证据验证仍属于提案。

## 复核结论与证据强度

当前主要问题不是“模型调用不够多”，而是任务约束、查询身份、检索命中、证据有效性与完成状态缺少清楚的执行契约。增加反思预算解决了一项接口可靠性问题，但没有解决这些语义问题；同时，最终重复是三种方法共有的现象，尚不能确定由RePAR机制、底座能力、上下文还是解码导致。

| 发现 | 实际证据 | 可以得出的结论 | 尚不能得出的结论 |
|---|---|---|---|
| 反思预算太小 | 高预算消融将首次截断34/46→0/42、修复36→0 | 原200-token反思预算确实妨碍完整JSON | 预算提高即可提高准确率；三项预算联动也未隔离每项贡献 |
| 最终质量基本未改善 | 实验分14.5→15.0，全对仍2/19，长度终止仍10/19 | 格式完整性与任务正确性不同 | 0.5分是稳定提升，或重复是RePAR独有问题 |
| 首轮问题保持 | 两条件19/19首计划、首动作逐字相同；无中文查询29/46→27/42 | 增加预算未改变最初的查询生成问题 | 英语查询一定导致每一题失败 |
| 约束被错误去重 | 独立fixture中`x>0`与`x<0`同签名；英文肯定/否定亦同 | 检索分词不能兼任调用身份；会在执行前误拦新约束 | 已能量化此bug对这19题分数的贡献 |
| 无相关内容仍返回片段 | 独立无词面命中fixture返回两个0分片段；原/高预算轨迹有9/15条零分树结果 | API没有如实表达无匹配，结果数量不等于证据量 | 任何低原始分数都应跨后端按同一阈值删除 |
| `exclude_passages`语义不符 | 独立单实体fixture明确排除C0，却返回C0 | 当前实现是降序优先级，不是严格排除 | 只修此参数即可保证图有帮助 |
| 中文预算失真 | 1.4万字符无空格中文被算成1词，10词记忆预算仍接纳整段 | 空白词数不是通用模型token预算；当前分段同样受影响 | 该fixture等同于本次每个实际请求都超窗 |
| 参数和终止受限 | 核心固定top_k=8、hops=2、方向both；空记忆无answer候选 | 执行器在合法性外还固定了部分检索参数及首次取证 | 当前实现完全没有自主规划或强制了树后图 |
| 图语义覆盖差 | 英语抽取器要求含拉丁字母；数学图98.97%为共现，乱码实体成枢纽 | 当前后端不适合泛化宣称中文数学关系支持 | 共现边永远无用，或更多谓词边必然提高准确率 |

复核脚本：[recheck_repar_general.py](../artifacts/maintenance/recheck_repar_general.py)；完整[复核记录](../artifacts/repar_general_review_20261119/review.json)。七项独立案例检查的是现有行为，不是已经通过的新实现验收测试。冻结源码与当前对应Python文件已核对，两个实验的协议、预测、判分及summary前后哈希未变。没有新模型调用。

## 保持不变的架构目标

继续保留`C/E/P/R`：有序树定位连续原文C，实体E、陈述P及关系R支持跨片段来源组合。索引只由原文、来源元信息和结构配置构建；题目、答案、分数不能进入建库。

继续采用`Plan → Action → 实际Observation → Reflection → 下一轮/回答`。规划与动作可以在同一次决策调用中表示；反思必须发生在真实工具结果之后。模型选择工具、参数与停止时机，执行器负责合法性、预算、出处和协议一致性，不固定“先树后图”、最低检索轮数或必用图。

通用入口支持无选项、无gold、没有外部知识库也可以处理的任务。选择题格式、benchmark答案解析及judge均留在适配层。下一版不是训练后的Self-RAG/Reflexion复现，也不宣称权重自进化。既有v2文献采用范围继续以[v2设计](REPAR_V2_DESIGN.md)为准，本文不新增未经核读的论文复现声称。

## 1. 先建立稳定的任务与执行契约

增加轻量`TaskSpec`，保留不可改写的`raw_task`、用户给定的范围/时间/否定等约束原文引用，以及输出契约、语言和可用知识源。模型产生的子目标和搜索focus只是对原任务的工作假设，不能覆盖原题或把待验证断言变成已知前提。

约束引用必须能回溯到原任务span，但“引用存在”不等于“语义解释正确”。新增、放宽或改变搜索假设要显式标为假设，例如找反例可以使用相反命题检索，并不等于修改任务。不能用“所有题干词都必须出现在查询里”的规则堵住自主搜索。

增加统一工具契约，分开表示：

- 执行状态：成功、无匹配、能力不支持、参数无效、资源耗尽或外部错误。
- 内容：真实来源引用、结构化输出、后端/语言/版本、raw score及其含义。
- 成本：实际模型token、工具耗时、输出是否截断、缓存来源。

`success`只表示执行成功，不表示检索相关、事实成立或任务完成。LLM相关性评估另存`model_assessment`，不能冒充工具已经验证。

API使用`response_schema`、`finish_reason`、usage与异常类型的统一返回，业务层完整验证字段类型、enum及引用范围，不只检查“JSON能解析且有required字段”。修复仅针对格式/截断，不重做已执行的工具；原响应、修复原因和所有尝试保留。

每次工具执行、观察和状态更新即时写入事件记录，生成格式失败或进程中断时返回/恢复已有有效状态，不能因为后续一次控制JSON失败而丢掉此前成功观察。恢复按真实请求及工具幂等身份判断，不将所有动作盲目重试；不同配置与代码版本不能续写同一条件。

## 2. 查询和参数化检索：保持原约束，允许真正组合参数

**分离检索表示和执行身份。** 检索可分词、词干化和去停用词；调用去重必须基于保留否定、比较符号、数量、变量、时间和scope的规范请求。空白和无意义排版可规范化，但不能把`<`与`>`、有/无、enabled/not enabled合并。近似重复只作带原因的候选警告或复用判断；不在无法证明等价时硬拦。重试同一真实请求和带新约束的新请求要分别留痕。

**将QuerySpec交给公共检索层。** 记录原任务锚点、模型当前focus、查询语言、约束引用及可选的同义/跨语言表示。原文锚点用于避免查询只剩翻译后的数字/字母，不强制每次检索原题全文，也不建立“必须先BM25”的研究路线。

基础后端先完善中英文符号/短语检索：保留公式与否定特征，允许语言匹配的词面查询。跨语言语义需要真正验证过的多语encoder或有记录的翻译后端；不是把英语prompt换成中文就宣称支持任意语言。encoder/翻译模型来源、版本、语言覆盖、额外调用和索引成本必须单列，不能静默换掉当前模型或把额外模型成本藏在RePAR中。

`tree_search`、`graph_entities`和`graph_neighbors`保留各自接口。公共query builder/lexical/dense算子供agent和baseline复用，核心不反向依赖baseline。需要多表示融合时，可在同一次搜索工具内部融合排名；它是搜索算子的实现，不规定agent跨工具的固定顺序。是否启用dense、融合或重排须独立配置/消融，原始分数不可直接当成可跨后端比较的置信度。

**输出真实的无命中。** BM25完全零匹配不为凑top_k补片段；dense无命中需按自身相似度定义及独立数据校准，不能照搬BM25阈值。无命中时让模型选择换focus、换语言/后端、浏览或回答不确定性，不能伪造“新增证据”。`exclude_passages`按契约严格排除；若需要允许旧来源但降低优先级，另给清楚的soft-preference字段，不能名实不符。

**模型控制有界参数。** 模型可以选择已观察/允许的scope与seeds、top_k、读取半径、方向、关系种类、hops和搜索模式，执行器验证ID、上限和剩余预算。catalog提供合法范围/能力，不预先只生成几条固定参数调用让模型选编号；也不任意开放没有出处的ID。优先实现单步一个动作，避免为减少LLM调用偷偷加入固定多步路线。

## 3. 以真实token预算管理来源、观察和记忆

分段以模型或索引声明的token计量，优先文档/章节、自然段和句子边界；中英文标点都支持，超长块按边界分窗。原文字节、canonical文本及规范化检索文本分开，规范化必须保留映射，不能“修正”原始公式后伪称原文。

知识库输入可以是连续字符串，另有可选`SourceMap`保存文档、页码、表格、语言和质量信息。保留来源元信息不等于采用原始chunk作为检索单元；可以重分段，同时将新span映射回原始出处。未知质量也必须是未知，不用任意分值替代。低质量片段留在存储和可读接口中，不静默删掉原文；乱码或解析失败不能成为实体身份、重要性或强关系的依据。

`EvidenceMemory`改为按当前focus、来源质量、覆盖、重复和token成本选择内容。保留检索到的全部原始记录，最终打包只选明确的span及其上下文；不因为最早出现或序号小而永久优先。相关性是可审计的估计，不能直接把排序当证明。压缩/摘要要标明生成结果与来源，关键限定、否定、数值、表头不可无记录地省略。

最终输入预算按服务实际chat template与tokenizer核验，预留最终输出、结构标签和工具消息；embedding窗口和生成窗口分别计量。来源预览、图路径、工具列表和摘要都占真实token，不能只对`text.split()`计数。离线分段不必绑定唯一生成模型，但必须记录计量器与超长块限制；换模型时重新核验实际prompt。

## 4. 图优化先解决实体身份和支持边界

将英语spaCy从“默认对任意文本抽取”改为声明能力的后端：语言、实体类型、关系种类、模型版本及解析失败统计可查询。中文/混合文本后端需要独立实现和验证；缺少支持时返回能力边界，树/原文接口照常可用，不伪造关系。模型依据这些能力选择工具，不强制使用或禁止所有图。

实体身份不能仅用全局规范短语决定。命名实体、通用概念、局部变量和文档内代号需类型与命名空间；两个来源里同名变量、同缩写、同符号不自动合并。跨片段/文档链接需别名或上下文证据，并保留候选链接、消歧依据及不确定状态。可靠的同一实体仍可跨来源连接，不能为了避免误合并把所有文档完全隔断。

关系继续保留方向、否定、情态、时间、条件和出处；增加句内/跨句抽取来源、解析器身份、局部实体绑定。共现只表示导航线索，不能自动升级为谓词，更不能串成结论。未知实体或乱码标记从语义枢纽候选中隔离，但原文仍可读。不要把减少共现比例或增加关系数作为精度目标。

图检索按query、路径关系、真实新增来源及已观察状态排序，抑制纯度低的高连接枢纽。去重看已获得的来源/命题/实际路径，不只看query文字；没有新来源但新增有效陈述也可有价值，应记录是什么。单纯返回新entity ID不自动计作任务进展。文档结构、来源映射、解析后端及其版本变化必须触发新索引身份。

## 5. 用结构化研究状态替代“有片段就算有证据”

在`ResearchState`中保留四类对象：

| 对象 | 内容与可信边界 |
|---|---|
| 原始来源 | 工具实际返回的quote/span及出处，不含模型新增事实 |
| 待验证陈述 | 模型提出的claim/子目标，附原任务依据和pending状态 |
| 推导/计算结果 | 依赖的来源与条件、实际计算输入/输出；模型推断和确定性验证分开 |
| 问题与冲突 | 缺口、互相矛盾的来源、失败检查、失效假设及下一步可选focus |

状态不是长篇思维过程，只保存对下一步动作和最终答案有用的短陈述、依赖及证据。`引用存在`、`模型认为支持`、`确定性检查通过`是不同状态；check只能证明自己检查的性质，不能把数值验证泛化成整个证明正确。

反思基于实际observation更新“哪些子目标有何新支持、哪些仍缺失/矛盾、下一步建议”。停止信号改名为`ready_to_draft`、`partial`、`no_progress`或`budget_exhausted`等真实含义，不把停止自动叫作“已经充分正确”。存在未解项也可以提交部分答案或说明不确定性，不能强制为满足状态继续检索或假装全部覆盖。

从第一步就允许直接形成答案草稿或提出缺失信息，不要求先获取片段。严格依赖指定来源的任务、允许自有知识的任务通过用户契约区分；前者缺少来源时可以解释不足，后者的自有知识要与来源事实区分。这个选择是通用任务语义，不是“数学题直接答”一类领域规则。

## 6. 让输出验证接到实际执行回路

通用入口增加有界`draft → 可选check → 记录结果 → revision/final`，而不是检索结束后另起完全失联的最终生成。草稿读取短研究状态、相关原文、未解项及输出契约；不注入全部历史或把未验证反思当事实。只有执行器允许的工具与预算可使用，任何新增验证调用都单列成本。

基础检查包括：响应是否空/截断、schema及引用是否存在、是否覆盖用户要求的输出项、是否循环重复。重复检测能判断退化迹象，不能确定重复部分数学/事实真假；需要中止或有限重试时留下partial/length/repetition原因，不剪掉难看的部分伪装成功。相同的通用输出可靠性组件应允许direct/BM25共用，对比同时报告共用后的条件，不能只给RePAR额外补答而隐藏成本。

可选能力使用统一`verify(input, assumptions, expected_property)`接口：确定性算术、代数表达式、日期区间、单位、表格汇总、结构查询等各由对应组件负责；模型选择需要的能力和参数，执行器约束合法输入、资源和返回范围。它不是数学benchmark专用判分，也不读取gold。一般自然语言论证可用独立评议，但仍是模型判断，不能称为形式证明；未装验证器时明确不可用。

首个v3迭代可以只做结构/出处/长度检查，后续再增加计算工具；不要为了新版本名称一次性引入通用任意代码执行。对于数学证明，符号运算或随机代入只可检查局部性质，不能自动认证任意证明。

## 实施顺序：先做可测契约，再做昂贵语义组件

| 里程碑 | 范围及建议落点 | 完成门槛 |
|---|---|---|
| R0：执行契约 | 新`contracts.py`，`text.py/workflow.py/retrieval/lexical.py`的请求身份、零命中与exclude语义；`client.py`增加保留原始结果的结构化接口 | 新独立案例能区分否定/不等式/数字/时间/scope；零命中真实；严格排除；旧API由明确compat模式保留 |
| R1：查询与记忆 | `retrieval/query.py`、`memory.py`、`index.py`及来源映射；真实token预算、查询锚点和有界参数 | 无空格语言不绕过预算；不改原约束；相关与无关来源可区分；已安装包仓库外可导入 |
| R2：研究与完成状态 | `workflow.py`、新的短状态模块；起始可draft/停止，真实进展及有限输出检查 | 可不检索；失败不冒充充分；模型无固定树/图路径；校验只能更新对应状态 |
| R3：图质量及可选验证 | `entity_graph.py/index_v2.py`后端接口、实体作用域、共现导航，按需新增`verification/` | 独立中英文/混合来源的身份、否定、方向、条件和出处核验；验证工具结果不能被过度解释 |

R0/R1应优先于新增encoder、大模型抽取或更多agent。可在R0完成后先做机制验证，再逐步叠加，避免同一次完整benchmark把所有变化混在一起。高预算profile作为可靠性参照保留，下一版字段应短而结构化并按schema实际开销配预算；不继续靠增加自由文本字段长度代替状态设计。

这是通用实现路线，不将表中的模块全部提前创建为空壳。真正新增包/接口时同步打包、导入、CLI、测试与文档；v2保持显式可复现，新入口/配置以`react-v3`、新index schema与新缓存身份隔离，验证通过前不改默认路由。

## 验证方案与底座归因

先建立独立开发fixture和冻结后新增的保留任务，不从这19道试卷抽题或拿答案挑参数。至少覆盖中英自由研究、单/多来源事实、相同名字不同实体、否定/时间/量词、数值/单位、无答案/冲突来源，以及不需要KB的任务；语义正确性依据独立构造的事实与实际执行断言。开发fixture用来修机制，保留任务用于后续确认；二者不能混称未见测试。

对照分层进行：

1. 同一底座/部署/最终预算：高预算v2、R0、再加R1、再加R2；可选图后端或验证器单独加入，不同时扩大行动轮数、温度、thinking或回答预算。
2. 检索算子在独立来源任务上先测目标来源覆盖、无命中、否定/约束保持、语言匹配与token开销；原benchmark没有相关性gold时不伪造“召回率”。
3. 图比较谓词/身份导航和弱共现导航的实际来源增益，同时运行无图对照；节点数和边数不作为效果指标。
4. 预算、结构化输出、检索及状态变化分别记录首次成功率、真实工具错误、修复、进展、停止原因、答案质量/引用支持、长度终止与重复、总token、离线建库和在线成本。
5. 若加入额外encoder、验证LLM或翻译，给出增加该公共资源的baseline控制；若加入额外补答，匹配或明确报告额外调用/预算。不能用“同最终底座”掩盖总资源差异。

**重复的底座检查单列，不归入RePAR改进分数。** 使用独立任务，在同一底座和相同最终prompt下固定证据，区分零外部context、简短相关context、较长context；先固定输出上限及解码，再独立改变输出预算，才能观察输入长度与输出长度的影响。没有控制长度/内容时，不能把direct、BM25、RePAR的差异全叫作长上下文效应。

更强底座、不同量化或thinking作为另一组显式模型/服务条件，同一套方法重新对照，报告资源、请求和judge身份；不能静默把评分27B拿来作答或混用缓存。同一模型自评/重复判分可能相关，对关键结论应有独立核验或抽查；没有充分证据前不声称排除了共同错误。

已曝光的数学集与LongBench可用于兼容及回归，必须披露曝光，不能继续作为未见确认数据。最终发布要同时展示负结果、失败与全量唯一ID，保留原始请求、响应和版本哈希；遇到共享硬件负载，不能按墙钟声称算法加速。
