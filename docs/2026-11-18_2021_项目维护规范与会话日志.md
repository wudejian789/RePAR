# 建立通用 agent 的持续维护约定

- 时间：2026-11-18 20:21，Asia/Shanghai（UTC+08:00）。
- 范围：本次项目维护规范会话；主要是文档与协作约定，不修改 agent 执行逻辑。

## 目标与背景

用户要求将 RePAR 作为可持续维护与更新的项目，生成 `AGENTS.md`，并在 `docs/` 按时间和摘要保存会话或重大改动记录。日志应汇总而非逐补丁记录；后续修复必须优先考虑通用性，避免针对 benchmark 的特例规则。

项目当前主实现为 v2：原文树定位片段，独立实体图关联跨片段知识，控制器执行 Plan → Action → 实际 Observation → Reflection。LongBench 的问题/选项、最终答案格式和评分位于适配层。

## 主要改动与决策

- 新增根目录 `AGENTS.md`，明确项目定位、核心不变量、目录职责、会话开始与结束约定、验证策略、结果来源及版本管理规则。
- 明确 BUG 修复应先定位所属层，使用任务无关的执行约束与独立通用案例；禁止将题目 ID、标准答案、领域关键词或固定树/图路线写入核心行为。
- 规定维护日志使用 `docs/YYYY-MM-DD_HHMM_简短摘要.md`，同一会话合并记录，重大独立变更可单列；原始工具输出、逐轮 trace 和运行中间产物继续保存在 `artifacts/`。
- 新增 `docs/README.md`，区分当前设计、历史设计、实验报告和维护日志，并提供索引。
- 同步根目录 README 的通用 agent 定位、维护入口和当前 v2 的知识/API/工作流说明，避免旧版描述被误认作当前架构。

## 通用性检查

本次约定将“通用任务与知识接口”和“benchmark 适配”明确分开。合法节点绑定、重复防护、格式恢复、出处核验和资源预算均按通用执行机制维护；不得依靠固定两轮、强制图访问或某一道题的特殊分支修复行为。

文档保留当前实现的能力边界：自动抽取关系不是经验证的逻辑证明，英语解析器不代表已经支持所有语言，任务内策略修订不等于权重自进化。新增研究能力时需要独立验证，而不能只根据当前测试集分数作结论。

## 验证与结果

- 核对维护文档所列的关键模块、配置、脚本和专题文档与当前文件布局、v2 默认入口一致。
- 检查新增文档和 README 的本地 Markdown 链接、日志命名及索引对应关系。
- 本次为文档改动，未重跑模型、benchmark 或运行时测试。此前的 v2 实验与 21 项测试结果仍是其当时版本的历史记录，本次不将它们重新声明为一次新验证。

## 兼容性、实验影响及未完成事项

不改变推理代码、模型选择、索引格式、实验配置、预测、原始调用记录或历史冻结 manifest。本次维护约定不影响已有实验结论。

后续每个有实质改动的会话应读取 `AGENTS.md` 和最近相关日志，结束时更新当前入口/设计和一份合并日志。不要依赖历史会话状态文件中的进程或进度判断当前服务状态。
