# 按基模推荐参数重跑两套评测

- 时间：2026-11-23 21:09，Asia/Shanghai
- 完成：2026-11-24 09:16，Asia/Shanghai
- 范围：两种基模的 16 个方法与数据集组合，每个组合重复三次，及 benchmark 推理参数维护约定。

## 评测设置

MATH 全国Ⅰ卷作答逐请求使用各基模 ModelScope 模型卡的非思考文本参数。0.8B 与 27B 分别使用温度 1.0 和 0.7、`top_p` 1.0 和 0.8、`presence_penalty` 2.0 和 1.5。二者都用 `top_k=20`、`min_p=0`、`repeat_penalty=1.0`，后者是 llama-server 接收的字段名。全部题型用自由文本和 4,096-token 最终上限，非选择题继续使用既有 27B 匿名评审协议和温度 0。[0.8B 模型卡](https://www.modelscope.cn/models/unsloth/Qwen3.5-0.8B-GGUF) · [27B 模型卡](https://www.modelscope.cn/models/unsloth/Qwen3.8-27B-GGUF) · [采样配置](../configs/benchmark_recommended_20261123.json)

LongBench 的所有方法使用官方脚本的温度 0.1、128-token 作答上限和四选一解析。按用户确认，采用同一份匹配官方答案格式的 GBNF，保留非思考模式。服务的其余采样项来自本轮核对过的冻结部署。新版维护约定要求优先使用模型发布平台的推荐值，官方脚本的显式规定覆盖相应设置，输出约束按整个 benchmark 统一。[官方脚本快照](../third_party/pred.py) · [维护约定](../AGENTS.md)

按用户要求，16 个条件均用 seed 42、43、44 重复作答，目标覆盖 48 次条件运行和 3,774 条逐题结果。首轮沿用已开始的 seed 42，后来两轮用独立的输出目录、协议和请求缓存。基线复用相同的资料，r27 在每个种子下重跑在线控制、检索和作答。MATH 每次都按相同的匿名阅卷协议打分。总表在一个条件的三轮均完成并核验后，取三个分数的算术均值，附上各轮成绩、时间及 token。[重复运行入口](../scripts/repeat_benchmark_recommended.py) · [三轮机器汇总](../artifacts/benchmark_recommended_20261123_repeats/summary.json)

## 数据与复用

两个 r27 MATH 条件使用同一份已验证的中文索引，共 2,180 个原文块。LongBench 的 r27 加载原有英语索引，重新执行在线规划、检索、反思和作答。基线复用归档的最终输入及其旧库来源。RAPTOR 有一题的历史作答阶段写盘失败，归档仍有 24 条检索证据，本轮从原证据恢复了答题请求。历史建库或检索未得到可用证据的题保留原状态，计入 LongBench 分母。建库计时和生成量用历史记录，表中答题计时来自新请求。基线计时从已归档输入开始，r27 计时还含在线编排，记录并发及排队影响。[运行入口](../scripts/run_benchmark_recommended.py) · [运行协议](../artifacts/benchmark_recommended_20261123/protocol.json)

0.8B LongBench 的 RAPTOR、HippoRAG2、HyperGraphRAG 每轮分别生成 121、9、121 份新答案。其余 4、116、4 题在历史建库或检索阶段缺少可复用证据，保留原终止原因并按 125 题统计。全实验共 3,402 条成功作答记录和 372 条历史失败记录。0.8B LongBench r27 在 seed 42 的恢复与重跑中命中本轮客户端请求缓存 34 次，含 3 次最终回答。其余条件与数学阅卷的客户端请求缓存命中数均为 0，各种子使用独立缓存身份。

## 运行修复

原入口在加载中文索引时替换了进程共享的查询分词器。续跑入口按每题所属条件设置查询分词器。MATH r27 使用 `zh_core_web_sm`，LongBench r27 使用其历史索引对应的词项处理。核对已生成的树查询时发现有三题的查询词项受影响，保留原始 trace 和作答，按正确分词重新执行这三题。[续跑入口](../scripts/resume_benchmark_recommended.py) · [恢复记录](../artifacts/benchmark_recommended_20261123/08/longbench/repar/recovery/)

另有一题的模型控制输出包含无法编码为 UTF-8 的 JSON 字符串。评测入口将这类输出纳入现有的控制格式修复流程，记录原始输出和修复请求后恢复作答。[Unicode 恢复入口](../scripts/recover_benchmark_recommended.py)
