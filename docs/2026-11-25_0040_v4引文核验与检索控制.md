## 控制协议

- Plan 用待核实的信息需求表示目标。面对多个待核实的说法，先规划要查的基础事实或关系。稳定 ID 和跨轮次进展沿用 r31。
- Action 自选工具与参数。树查询、浏览和图查询的 `top_k` 可省略，执行时使用配置值，r32 配置为 8。模型可根据明确线索请求更少条数。默认值在执行去重前绑定，省略参数和显式指定默认值视为同一请求。
- Reflection 为部分或全部覆盖的目标给出来源 ID 和原文引文，然后总结事实及剩余缺口。执行器只接受能在本轮可见窗口或已核对的图陈述原文中匹配的引文，匹配时折叠空白。引用真实存在与证据支持结论仍是两项独立判断，后者由模型完成。
- 目标覆盖更新和任务停止决策各自生效。Reflection 发出 `continue` 时，下一轮仍可查证已覆盖的目标。若用于报告进展的引文无法核验，同时收到 `answer`，执行器把被拒绝的更新反馈给下一步 Action。资源预算和无进展机制约束整个循环。Action 可根据已有证据自主作答。

普通任务入口为 `python scripts/research_kb_v4.py --config configs/repar_v4_r32.json`。查询语言、图及原文接口遵循同一协议。版本显式选用 r32，索引结构兼容已有库。[r32 配置](../configs/repar_v4_r32.json) · [目标与引文校验](../src/repar/v4/objective_state.py) · [Action 参数](../src/repar/v4/objectives.py) · [执行循环](../src/repar/v4/workflow.py)
