# Baseline 目录整理与 BM25 RAG 迁移

- 开始时间：2026-11-18 20:26，Asia/Shanghai（UTC+08:00）。
- 范围：本次目录重构会话，合并记录实现、验证和维护约定调整。

## 目标与背景

用户创建 `baselines/` 并要求后续 baseline 按方法归档，其中 BM25 RAG 应从 agent 中独立。用户同时指出，AGENTS 不应固定“当前主要实现为某版本”等易失信息；版本、配置和实验状态应由 README/日志维护。

目录统一采用复数 `baselines/`，BM25 放在 `baselines/BM25_RAG/`，不再建立平行的 `baseline/` 目录。

## 主要改动与决策

- 将 BM25 独有的检索器、通用单轮 RAG、独立命令及 LongBench 适配整理到 `baselines/BM25_RAG/`；方法不再依赖 agent 的规划/反思流程。
- `repar.cli --method bm25` 直接分发到 baseline，不为纯 BM25 构建树/实体图。历史 agent 的同名方法保留薄委托，原实验和页面方法 ID 不变。
- 无损分段、分词及 BM25 排序抽为 `repar.text`、`repar.retrieval.lexical` 公共组件，树检索与 baseline 复用同一算子。保留原排序公式、参数、同分排序与子树范围行为；不将公共算子复制到两套实现中。
- 原 `repar.index.terms` 与 `split_spans` 继续作为兼容导出，已缓存索引与向量化器仍可解析其历史模块引用。
- 更新 Python 包发现与 README 打包设置，使 `baselines` 和子包在可编辑安装和 wheel 中可用，不依赖仓库当前工作目录。
- AGENTS 改为稳定的项目定位、职责目录和维护规则，移除当前版本、模型服务地址、机器解释器路径及固定测试数量；当前信息留在 README/配置/报告。
- 目录职责明确为：`baselines` 放对比方法，`models` 放模型权重，`data` 放原始数据，`artifacts` 放结果/缓存/索引，`scripts` 保持薄入口。既有数据/模型路径维持兼容，新增资源按名称归类。

## 通用性检查

BM25 的普通检索与作答接口接收自由任务和知识原文，不处理选项、标准答案或评分。benchmark 专用 prompt/解析只在 `adapters/`；独立命令的纯检索模式不需要模型服务，生成模式不使用选项字母约束。

本次是组件边界和安装结构重构，没有加入领域关键词、特定题目规则、固定树/图路线或按测试成绩选参数。已有125题只作为迁移兼容性夹具，比较原请求和证据，而不是依据答案优化算法。

## 验证与结果

- 26 项测试通过：包含原测试、BM25 独立任务/原文出处、排序与范围兼容、历史入口委托、纯 BM25 不构建树/图、纯检索命令及前端集成。
- 对全部125题运行离线迁移审计：选中片段 ID、模型请求 JSON、请求身份、记录的回答/预测与上下文哈希均与原标准 Q4 BM25 记录一致。未调用生成模型，未声称新增准确率实测。
- 可编辑安装与 wheel 构建成功；从仓库外使用隔离 Python 导入 baseline 及其适配层成功。
- 从 wheel 解包后的独立位置执行纯检索成功，确认 README 与所需包均包含在分发中；原有树/实体图缓存仍可加载，共用词法排序一致。
- 核对目录说明与 Markdown 链接；具体审计输出在 `artifacts/maintenance/bm25_migration_validation.json`。
- 本次源码/打包检查单独记录在 `artifacts/maintenance/2026-11-18_2026_baseline_reorganization.json`；构建目录加入忽略规则，不作为项目业务目录。

## 兼容性、实验影响及后续入口

原始预测、数据、模型、配置和历史冻结 manifest 不修改。本次源码迁移另作维护记录，不能将旧 manifest 的源码哈希视为新目录结构的快照。独立 BM25 构建统计只记录实际词法索引成本；历史记录中包含的旧树/图构建统计仍保留原值，不重写为新耗时。

当前实验 `--method bm25` 可继续使用；新方法按 `baselines/<Method>/` 增加实现、适配与 README，并同步打包、导入、测试和文档。通用 agent 的算法能力、默认模型和评测格式不因目录整理改变。
