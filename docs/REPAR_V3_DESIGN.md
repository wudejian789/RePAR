# RePAR v3：检索核心修订

2026-11-19，用户明确否决了此前混入v3的四项扩展：按任务分类决定作答门槛、添加算术或符号计算工具、最终答案结构化及字段恢复、额外答案复核。可在其他场景复用一项功能，并不足以证明它属于本轮RePAR通用机制的改进。

当前内部标识为react-v3-core-r1，名称仍为RePAR v3。[此前四组实验](REPAR_V3_EXPERIMENTS.md)及冻结源码保留为被否决方案的历史记录，不能把旧分数归给当前修订。默认入口仍为v2。

两种底座、v2/v3与无图对照的事后诊断见[跨底座分析](2026-11-19_2027_RePAR跨底座分析与通用改进.md)。2026-11-19 21:04按用户要求更新分析链接；后续实现见带时间的v4文档，本设计下文仍描述真实已测v3实现。

## 长期边界

- 核心不枚举参考资料、文档依赖、自足等任务类型，不再提供source_required分支，也不以预设分类规定作答方式。
- 不通过逐个增加专用工具覆盖预想场景。工具保持v2的树搜索、树浏览、原文阅读、实体查询和实体邻居查询，移除计算器和表达式修复。
- 重复吐词等生成问题在底座模型、推理服务和generation配置层处理，workflow不为此增加最终答案JSON、字段恢复、复核或重答环节。后续换模型或调解码独立版本化和验证。
- 研究过程中的Reflection仍在真实工具执行后进行，用于下一步计划与检索；它不等于已删除的最终答案复核。

以上边界已写入[AGENTS.md](../AGENTS.md)。

## 当前保留的机制

1. **参数化查询选择**：合并短计划与工具选择，由模型在合法范围内选择检索范围、top_k、beam_width、模式、图方向/关系类型/跳数及阅读半径。工具引用绑定已观察节点，执行器不规定树/图路线。
2. **查询执行语义**：请求身份保留数字、符号、否定和scope；重复动作在执行前阻止。检索焦点保留原任务锚点，零匹配不补无关片段，排除来源保持严格语义。
3. **原文证据预算**：用当前模型tokenizer控制来源和预览预算，在运行时选择连续原文窗口并记录字符偏移。研究暂定发现保留在轨迹，不作为最终事实前提。
4. **已观察引用的可达性**：原文记录返回的实体进入可用实体集合；树浏览返回的子节点进入可用scope集合。此前v3只接收顶层实体结果，忽略原文记录携带的实体，已观察到的实体不能直接用于邻居查询。现已接通引用，不强制模型查询图。

这些机制尚需独立消融，契约修复和单元测试通过不代表准确率提高。原教材、格式、片段划分、树和实体图均不重写或重建；英文图后端对中文的覆盖限制仍在。

## 与v2对齐的部分

沿用v2的作答可用性和停止语义：观察到原文片段后提供answer动作，模型反思可选择继续或回答，另受资源与无进展预算限制。没有新增任务分类或强制弃答规则。

核心只返回研究结果和来源，最终生成由调用者或评测适配器负责：

- 通用CLI：沿用v2自由文本提示和512-token作答预算。
- MATH：沿用v2的solver_messages、原始回答及4096-token上限。
- LongBench：沿用官方RAG提示、128-token输出上限和原grammar。

无来源时也按原适配器生成回答，不引入特殊弃答文本。最终输出原样记录，即使看起来像不完整JSON，也不猜测或恢复字段。Action消息仍校验参数结构，限于查询API合法性。
