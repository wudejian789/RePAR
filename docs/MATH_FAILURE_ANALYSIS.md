# 全国Ⅰ卷数学补测的失败诊断

RePAR本轮14.5/150，低于BM25的25/150。逐题核对后，差距主要来自三道选择题的最终作答退化，叠加查询改写、中文检索/图适配及控制协议问题；不能把它简单解释成“4096 tokens不够”或“judge太严格”。以下是对冻结v5历史记录的事后分析，没有重新调用模型、调参、改分或改写历史实验。

原始[完整报告](../artifacts/math_2025_national_i_v5/REPORT.md)、[机器诊断](../artifacts/math_2025_national_i_diagnosis_20261119/diagnosis.json)及[离线分析脚本](../artifacts/maintenance/diagnose_math_failure.py)可复核。诊断导入本次冻结算法源码，避免其他会话对工作目录的修改混入结论。

归因澄清：重复在direct/BM25中同样存在，因此此处的最终作答失败是现象分类，不能将其当作RePAR独有缺陷或已确定的算法根因。底座、长上下文、长输出及解码配置可能产生共同限制，尚无隔离对照证明其“固有性”。用户指定先增加中间token预算，独立[预算消融](MATH_INTERMEDIATE_BUDGET.md)保持底座和最终输出不变；其结果与原实验分别保存。

## 1. 4096-token截断多数伴随重复与题意漂移

| 指标 | direct | BM25 | RePAR |
|---|---:|---:|---:|
| 最终输出达到4096 tokens | 12/19 | 9/19 | 10/19 |
| 选择题未解析出规范最终选项 | 5/11 | 4/11 | 9/11 |
| 解析失败且长度终止 | 5 | 4 | 8 |
| 长度终止且有同一长行重复至少3次 | 10 | 8 | 8 |

重复指标仅按去除行首列表/Markdown后、长度至少20字符的完全相同行计算，是保守的文本诊断，不是语义判分。RePAR Q1将“如果题目是(1+5i)i，虚部是1”这一长行重复41次；Q17同一勾股关系重复117次。Q3没有缺少双曲线资料，却额外假设一个题目没有的斜率限制，造成虚假的题目矛盾。这种输出不是健康推导刚好超长。直接加大上限是否能改善分数没有做反事实实验，不能作保证。

RePAR另一个解析失败是Q9：它以Markdown标题加下一行`B C D`结束，不符合预定同一行格式；但D本身选错，改成宽松解析仍不会变成正确答案。故9次解析失败不能都算作“只差格式”，也不能都当作已明确作出了错误选择。原评分保持不变。

## 2. 查询语言不匹配，且改写会改变条件

46轮实际查询中29轮不含汉字；19题有8题首轮就是不含汉字的英语/公式查询。当前TF-IDF、BM25与实体搜索主要用词面匹配，没有跨语言语义对齐。英语的`ellipse`、`independence test`不会自动匹配“椭圆”“独立性检验”；数字和公式碎片可能反而主导排序。

Q15实际首轮英语查询检索到了潮汐水深、二分法、用水量、封面、目录和集合章节，其中5个结果得分为0，仍被API补足返回。用原始中文公开题干做离线BM25检查，前列出现独立性检验章节C530～C534。Q18的英语查询先找到平行线距离、两圆关系、三角函数和数据表；公开题干离线检索则找到椭圆离心率等内容。这只是事后来源检查，没有生成替代答案或宣称测得召回率。

规划还有直接的条件漂移：

- Q14把“有放回地取三次”写成“不放回地取三次”，随后检索与反思讨论了错误的抽样场景。之后查询虽改回有放回，最终仍把不同球数错误当成固定某个球的二项分布计数，得3/5。
- Q18把下顶点、右顶点改写成`A(0,−b²)`和`B(b²,0)`。
- Q9第二轮把判断选项改成“证明AD平行于A₁B₁”，提前把错误选项当作要证的前提。
- Q7后续查询没有保持“有且仅有2个”的关键数量约束。

独立构造的“档案馆/天文台”中文两段fixture验证：英语光谱查询在当前BM25中两段均为0分，中文对应概念能命中天文台。它验证了词面检索的语言边界，不需要本试卷答案。

## 3. 图主要是OCR共现，不能提供可靠中文数学关系

冻结图有12759个实体、14682条关系，但其中14531条（98.97%）为`co_mention`，谓词关系仅151条。1770个实体名带`UNRESOLVED`标记；按跨片段出现次数排序，最高连接实体就是`UNRESOLVED_U+E5C6`，还包括`b,c`、`c o`等局部符号。这些高连接不能视为稳定、跨题可复用的数学概念。

实现采用英语`en_core_web_sm`名词短语/依存分析，并要求实体名包含拉丁字母，纯中文概念因此被过滤；纯中文实体名计数为0。部分中英混合实体确实含中文（9005个），所以不能把它误说成“完全没有中文内容”，但也不表示中文概念边界和关系已可靠抽取。

实际轨迹中Q15沿`b,c`跨到集合/排列内容；Q16选择了`6 3\n一般式 ge`等解析碎片；Q1也选择过包含乱码的节点。11次图邻居调用有7次没有新增原文片段；可能仍有实体元数据变化，不能等价说成工具完全没有返回，但没有提供新的原文覆盖。200条树检索返回中有9条零分来源。所有这些都能在原轨迹核对。

这说明“确实用了图”“工具无错误”与“图对解题有帮助”是不同事实。当前图在中文OCR数学教材上没有足够有效的语义支持。没有运行同条件无图消融，不能把10.5分差全部归因于图。

## 4. 控制器的反思与停止信号不稳定

46轮反思首次生成有34轮达到200-token上限并形成不完整JSON；随后有36次额外修复调用，包括2次第二次修复。计划和动作均未产生修复，瓶颈明确集中在反思的多字段、来源列表与过小预算的组合。另有19次assessment、19次gap、24次lesson恰好达到schema字符上限，可见不少“合法JSON”仍停在半句。

25/46轮objective只是“Plan one next step…”一类通用复述，没有形成具体研究目标。16题被标记`model_sufficient`，其中13题最后得0分。这个标签仅代表模型停止信号，执行器没有核验已经完成数学计算或证明。Q4、Q16甚至出现“failed/insufficient evidence”与`next=answer`并存，不能把它视为证据充分。

当前工具只有树、实体、邻居与原文阅读，没有实际执行的代数计算或证明检查。反思主要评价有没有检索到资料，不是对最终解答的执行后验证；最后答案生成后也没有检查算术、约束或重复。

最终作答另起一次请求，只接收原题和原文证据，不接收controller的plan/reflection/policy状态。反思可以影响后续检索，但没有形成持续累积、可核验的解题中间状态，不能把当前流程理解成“推导—计算验证—改错”的数学agent。若要传递中间结论，也需区分已验证推导和模型猜测，不能直接把未核验的反思升级为事实。

另外，当前候选动作在原文记忆为空时没有`answer`，简单任务也必然先获取外部原文；这是控制策略的结构性约束，不是模型自主判断每个题目都需要检索。独立fixture确认这一行为，但没有实测取消约束后的分数。

## 5. 底座数学能力与教材质量是共同限制

作答底座是0.8B标准Q4、关闭thinking；27B只负责评分。所有方法在5道解答题上均无整题全对，且各自出现递推通分、概率、几何和三角运算错误。RePAR Q16将不同分母下的差直接当成分子差，Q18将顶点间距误认为焦距，错误在最终推导中实际存在，无法靠更多相邻文本保证纠正。

这是当前底座/推理配置的能力表现，但没有做更强底座或不同推理模式对照，不能定量归因于参数规模或Q4量化。三方法同底座，所以仅说“模型小”也无法解释RePAR额外丢掉的三道单选题。

教材1110条原记录中248条failed、719条low_confidence，本轮全部保留；公式中的上下标、分式、表格与乱码尤其会影响词面检索及数学阅读。切分仍按空白词而不是中文token/段落语义，产生547段，中文、公式和其他例题混杂。Q3虽然拿到了核心公式，检索还加入了多个无关练习；最终答案把来源中的其他限制混入题干。轨迹支持存在这种混淆，但不能仅凭文本证明某一句幻觉究竟由哪一段来源引起。

## 修复优先级与结论边界

优先在通用机制层验证以下改动，而不是针对本试卷加提示词规则：

1. **作答可靠性**：针对重复、题干条件保真、最终答案结构和简单运算建立独立案例；区分长度终止与格式失败，先验证结束/修复机制，再决定是否增加预算。任何有模型调用的补答或验证都要报告额外成本。
2. **查询与知识表示**：提供语言匹配或真正多语检索，保留关键条件、否定及数量约束；零相关度明确返回无命中，不把补足的零分片段当证据。用独立中英文任务验证，不拿试卷答案选查询。
3. **中文图与OCR来源质量**：实现并验证中文实体/关系后端、公式与概念的类型边界；乱码标记不能成为语义枢纽。能力不足时明确报告边界，是否查询/使用图应由任务、可用性及真实反馈决定，不能强制树/图顺序。
4. **控制与验证**：按实际token及schema开销设定反思预算，检查停止理由与证据状态；让执行器保留可验证的中间结果，并考虑通用计算/约束验证接口。不能把未核验反思直接当结论，也不能声称已复现经过专门训练的反思模型。
5. **重新评估**：独立案例通过后，使用新版本、新缓存身份做预定完整对照；若做数学任务，另设同底座、无外部上下文的条件，可区分教材辅助与干扰。更换底座或thinking必须单列条件，不能混入历史结果。

本次只完成诊断、独立机制检查和文档，没有实施以上算法改动或发起新模型实验。历史预测、评分、协议、summary和冻结源码哈希均未改变。没有再次执行整套应用测试，原因是核心代码/配置未修改；分析脚本的4项独立机制断言实际通过。所有发现均为已经看过测试结果后的事后诊断，不是未见数据的确认实验。
