# 项目文档与维护记录

更新时间为 2026-11-28 00:33，Asia/Shanghai。

RePAR 是通用知识 agent。LongBench v2 是当前评测场景，不能成为核心协议、知识表示和 BUG 修复的特例来源。长期维护规则见根目录 [AGENTS.md](../AGENTS.md)，当前使用入口见 [README.md](../README.md)。

## 当前设计与实现

- 用户确认 Direct answer 8K、seed 42 为最终 v5；0.8B / 27B 的两套评测已全部完成并审计，24 个组合中 16 个已有结果、8 个未测填“-”。[最终指标总表](2026-11-27_2019_v5双底座最终结果与基线指标汇总.md) · [最终条件登记](../configs/v5/final_results.json)

- v5 将模型的先验草稿带入 r61 的自主检索循环。研究工作台按会话组织问答，逐轮选择知识库，按当轮的库回读出处。知识库管理提供建库和 2D、3D 图谱，评测页可逐题复核 v5 的冻结记录。[v5 设计与评测](2026-11-26_1707_RePARv5先验草稿与研究工作台.md) · [工作台改版](2026-11-27_1047_问答工作台与评测案例重设计.md)

- r60 以 EmbeddingGemma 做 token 分块、树路由及原文片段向量检索，spaCy 继续抽取实体和关系。追加了种子 42 的 r60/r61 768 与 1024-token 对照及 token 用量。[r60 分块与向量索引](2026-11-26_0327_r60分块与向量索引.md)

- r27-hope3 为当前缺口提出首选和可选备选，执行一次后即根据实际返回反思。[r27-hope3 与最早 r27 三种子结果](2026-11-26_0201_r27-hope3与历史种子复测.md)

- r27-hope2 用当前证据缺口生成查询，Action 可以在一次请求中提交多个独立调用，Reflection 读取该批的实际返回。[聚焦查询与批量行动](2026-11-26_0115_r27-hope2聚焦查询与批量行动.md)
