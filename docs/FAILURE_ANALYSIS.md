# 本轮结果与失败分析

本轮完成了全部 1,500 个预测和原始 API 记录审计，但没有实现“小模型 RePAR 超过论文 GPT-4o 44.0%”的目标。它是可运行、可复核的研究原型，不能作为已经验证有效的 RePAR 方案。

## 能直接支持的结论

标准 Q4 的 RePAR 为 25/125（20.0%），直接回答为 26/125（20.8%），BM25 为 29/125（23.2%）。RePAR 相对直接回答的配对差为 -0.8 个百分点，bootstrap 95% 区间 [-9.6, 8.0]；相对 BM25 为 -3.2 个百分点，区间 [-12.0, 5.6]。本实验没有证明额外编排带来精度收益。各方法接近四选一的 25% 随机参考水平；这不等于模型实际随机作答，也不能据此证明此底座在所有提示、thinking 设置和检索后端下均无法完成任务。

结构本身可以构建并查询：125 个独立上下文、45,783 个叶片/知识节点、67,057 个树节点、700,754 条边；130,898 个抽取命题的出处和树覆盖均通过审计。冷构建累计约 163.6 秒。已加载索引的查询平均耗时约为树 3.47 毫秒、两跳图 1.29 毫秒。该审计证明结构一致性和本次规模的查询开销，没有证明证据召回质量。

控制器执行质量明显不足。标准 Q4 全部 125 题均耗尽 5 轮；625 次控制器输出中有 615 次同时声明 finish 并选择工具，出现 391 次重复成功调用错误，仅 2 题使用图查询。MTP 权重的关闭/开启两组都没有成功的图查询。JSON Schema 消除了本轮的格式解析错误，却没有保证模型理解停止、查询修订和跨证据取证的策略。

禁用图的标准结果为 24/125，与完整 RePAR 只差 1 题。由于只有 2 题访问图，这个消融主要揭示控制器几乎没有利用图；它不能检验“一个能熟练使用图的 RePAR 是否更有效”。策略字段的文字变化也不能代替有效的行为改进。本实现只具备任务内策略修订机制，没有证据表明已达到稳定的 RSI 或自主研究能力。

## MTP 决策

同权重 MTP 开启/关闭的直接回答分别为 32/125 与 30/125；RePAR 分别为 27/125 与 28/125。RePAR 少 1 题，配对差 -0.8 个百分点，95% 区间 [-5.6, 4.0]。这符合本轮工程判据的可接受小幅波动，但不能证明严格的统计等价，更不能把直接回答多 2 题解释为 MTP 提升了模型能力。

速度不满足用户要求。短上下文探针的解码吞吐从 370.0 降为 256.8 tokens/s，减少 30.6%；RePAR 平均服务计算从 4.813 增为 5.017 秒，增加 4.2%，客户端墙钟从 5.112 增为 5.327 秒，增加约 4.2%。直接回答服务计算从 11.100 增为 14.345 秒，增加 29.2%，主要差异在预填充。

MTP 确实启用：启动参数、MTP 上下文初始化日志、非零草稿生成与接受计数互相印证。探针草稿接受率约 25.5%，RePAR 约 49.1%。在这个很小的 target 模型、RTX 3090、llama.cpp b12500、最多 6 草稿 token 的配置中，草稿和验证开销未换来明显提速。因此默认关闭 MTP，并恢复标准 Q4 服务。没有测试所有草稿长度和服务实现，不能宣称所有 MTP 配置都慢。

## 仍需独立实验验证的方向

这些是下一轮候选设计，不是已完成的改进，也不使用本测试集答案来调参：

1. 在独立开发语料上验证适合 0.8B 的简化控制协议。将选择动作、生成参数、观察后判断缺口分开，减少每轮提示长度；以真实新增证据、重复率、图桥接成功率和停止合法率验收，再冻结协议进行独立评测。
2. 为文档、章节、时间段保留显式边界，并用可替换的语义编码器、实体归一化和原子命题关系抽取增强知识结构。现有 TF-IDF 概念边只是词汇关联，尚未实现用户设想的可靠逻辑关系图。需要独立标注的小规模证据集衡量召回、跨文档桥接和出处正确性。
3. 在证据预算相同的条件下比较单次检索、多轮树查询、树加图、固定编排和自主编排，另加 thinking/独立推理步骤对照。当前直接答案使用关闭 thinking 的短格式生成，不能把此设置的失败等同于底座能力上限。
4. MTP 可在相同输入的独立探针上搜索草稿长度与部署后端，再对锁定候选作完整准确率和速度验证。吞吐优化不应依靠 LongBench 标准答案选择设置。

完整数值、分组与原始材料见 [实验报告](EXPERIMENT_REPORT.md)。
